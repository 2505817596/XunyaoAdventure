# 邮箱系统

## 模块定位

邮箱系统用于向玩家发送系统邮件和附件奖励。当前实现覆盖玩家收件箱、邮件详情、附件领取和后台发信。

邮箱数据属于玩家运行数据，使用 LiteDB 持久化。

## 玩家入口

主页入口：

```text
/
 -> 邮箱
```

如果存在未读邮件，或存在未领取附件的邮件，主页按钮显示数量：

```text
邮箱（3）
```

## 页面结构

页面路由：

```text
/mail
/mail/{mailId}
```

`/mail` 是邮箱首页，只显示邮件列表，不展示正文和附件详情。

列表项显示：

- 邮件标题
- 发件人
- 发送时间
- 阅读状态
- 附件提示

附件提示只显示摘要：

- `无附件`
- `有附件`
- `附件已领取`

点击列表项进入 `/mail/{mailId}`。

`/mail/{mailId}` 是邮件详情页，显示：

- 标题
- 发件人
- 发送时间
- 正文
- 附件列表
- 领取附件按钮

进入详情页时自动标记邮件为已读。

## 后台发信

后台入口：

```text
/admin/mail
```

后台可填写：

- 玩家账号
- 标题
- 发件人
- 正文
- 附件列表

附件类型沿用 `QuestReward`：

| 类型 | 说明 |
| --- | --- |
| `Copper` | 铜钱 |
| `Consumable` | 道具 |

道具附件必须选择 `items.json` 中的道具模板。

## 数据模型

运行模型：

```csharp
MailMessage
```

字段：

- `Id`
- `UserName`
- `Title`
- `Content`
- `SenderName`
- `SentAt`
- `Read`
- `Claimed`
- `Attachments`

附件使用：

```csharp
QuestReward
```

## 持久化

LiteDB 集合：

```text
mail_messages
```

文档模型：

```csharp
MailMessageDocument
```

字段：

- `Id`
- `UserName`
- `Title`
- `Content`
- `SenderName`
- `SentAt`
- `Read`
- `Claimed`
- `Attachments`

集合索引：

- `Id` 唯一索引
- `UserName` 普通索引

## 领取规则

领取附件流程：

```text
校验登录
 -> 查找玩家自己的邮件
 -> 校验附件是否存在
 -> 校验是否已领取
 -> 调用 GameAccountStore.GrantRewards
 -> 标记 Read = true
 -> 标记 Claimed = true
 -> 保存邮件
```

奖励发放复用账号奖励逻辑，不在邮箱里重复维护背包写入逻辑。

账号更新规则仍然是：

```text
先更新内存
再保存 LiteDB
```

## 状态含义

| 字段 | 含义 |
| --- | --- |
| `Read` | 玩家是否打开过详情页 |
| `Claimed` | 附件是否已经领取 |

没有附件的邮件只需要读信，不需要领取。

有附件的邮件即使已读，只要附件未领取，主页仍计入提醒数量。

## 当前限制

- 暂无群发。
- 暂无邮件删除。
- 暂无过期时间。
- 暂无一键领取。
- 暂无邮件模板配置。
- 暂无装备附件。
