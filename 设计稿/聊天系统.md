# 聊天系统

## 模块定位

聊天系统用于玩家交流、好友私聊和系统公告展示。当前实现为 Blazor Server 实时刷新 + LiteDB 持久化。

## 当前频道

| 频道 | 说明 |
| --- | --- |
| 世界 | 已登录且已创建角色的玩家可以发送消息，所有玩家可见 |
| 公会 | 已加入公会的玩家可以发送消息，仅同公会成员可见 |
| 私聊 | 好友之间一对一发送消息，仅发送方和接收方可见 |
| 系统 | 只显示系统公告，玩家不可发送 |

## 数据模型

`ChatMessage`：
- `Id`：消息自增 ID。
- `Channel`：频道，支持 `World`、`Guild`、`Direct`、`System`。
- `SenderUserName`：发送者账号。
- `SenderDisplayName`：发送者角色名。
- `Content`：消息内容。
- `SentAt`：发送时间。
- `IsSystem`：是否系统消息。
- `GuildId`：公会频道所属公会 ID。
- `RecipientUserName`：私聊接收方账号。

`DirectChatSummary`：
- `FriendUserName`：好友账号。
- `LatestMessage`：该好友会话最后一条私聊消息。
- `UnreadCount`：该好友会话未读消息数。

`DirectChatReadState`：
- `UserName`：玩家账号。
- `FriendUserName`：好友账号。
- `LastReadMessageId`：该玩家对该好友会话最后已读消息 ID。

## 存储规则

- 使用 LiteDB 集合 `chat_messages` 持久化消息。
- 使用 LiteDB 集合 `direct_chat_read_states` 持久化私聊已读位置。
- 内存和数据库最多保留最近 `120` 条聊天消息。
- 启动时从 LiteDB 加载历史消息和私聊已读状态。
- 如果没有系统消息，启动时写入欢迎消息。

## 发送规则

- 必须登录。
- 必须已创建角色。
- 不能发送空消息。
- 单条消息最多 80 个字。
- 同账号同频道发送冷却为 800ms。
- 发送时压缩多余空白，避免纯空格或大量换行刷屏。
- 公会频道发送前校验玩家是否属于该公会。
- 私聊频道发送前校验双方是否为好友。

## 私聊规则

- 私聊入口为 `/chat/{FriendUserName}`。
- 好友列表中的“私聊”按钮会进入对应好友私聊窗口。
- 首页聊天摘要如果最新消息是私聊，点击后进入对方聊天窗口。
- 删除好友后，历史私聊保留，但不能继续发送私聊。

## 未读规则

- 私聊未读按“当前玩家 + 好友账号”维度计算。
- 只有对方发给自己的消息计入未读。
- 自己发送的消息不计入自己的未读。
- 进入对应私聊窗口时，自动标记该会话已读。
- 玩家停留在当前私聊窗口时，如果收到该好友新消息，也自动标记已读。

## UI 入口

主页：
- 聊天摘要显示当前玩家可见频道的最新消息。
- 好友按钮显示私聊未读总数，例如 `好友（3）`。

聊天页：
- 世界 / 公会 / 私聊 / 系统频道 Tab。
- 消息列表。
- 世界、公会、私聊频道输入框和发送按钮。
- 系统频道只读提示。
- 字数统计。
- 返回主页按钮。

好友页：
- 好友列表显示每个好友的最近私聊内容、时间和未读数量。
- 点击“私聊”进入对应好友聊天窗口。

## 首页摘要

首页聊天摘要显示当前玩家可见的最新消息：
- 世界消息对所有人可见。
- 系统消息对所有人可见。
- 公会消息只对同公会成员可见。
- 私聊消息只对发送方和接收方可见。

摘要标题根据消息频道显示：
- 世界聊天
- 公会聊天
- 好友私聊
- 系统消息

## 刷新机制

`ChatStore` 在消息变化和私聊已读状态变化时触发 `MessagesChanged` 事件。

聊天页、好友页和主页订阅事件后通过 `InvokeAsync` 刷新 UI，因此多个 Blazor Server 会话可以看到实时新增消息、未读数变化和会话摘要变化。
