# 后台配置系统

## 模块定位

后台配置系统用于管理游戏静态 JSON 配置，也提供少量运营操作入口。

当前后台入口：

```text
/admin
```

## 配置文件

配置文件目录：

```text
App_Data/Configs/
```

配置文件：

```text
monsters.json
items.json
campaign.json
quests.json
gameplay.json
gacha.json
```

配置文件由 `GameConfigStore` 读取和保存：

- 启动时读取 JSON。
- 文件不存在时生成空配置文件。
- 后台保存后写回 JSON。
- 保存后刷新内存配置。
- 配置错误时返回中文错误提示。

## 初始化配置

页面：

```text
/admin/gameplay
```

保存到：

```text
gameplay.json
```

可配置：

- 初始账号等级
- 初始铜钱
- 默认关卡
- 默认阵容数量
- 创建角色赠送妖怪模板列表
- 公会等级上限
- 每个公会等级所需总贡献

## 妖怪配置

页面：

```text
/admin/monsters
/admin/monsters/{templateId}
```

保存到：

```text
monsters.json
```

可配置：

- 模板 ID
- 名称
- 主属性
- 元素
- 站位
- 初始等级
- 初始星级
- 初始阶级
- 初始战力
- 战斗资源 ID
- 头像路径
- 基础属性
- 成长属性
- 战斗参数

## 物品配置

页面：

```text
/admin/items
/admin/items/{kind}/{templateId}
```

保存到：

```text
items.json
```

物品分类：

- 道具：`consumables[]`
- 装备：`equipment[]`
- 碎片：`fragments[]`

物品模板配置图片路径 `imagePath`。前台通过模板 ID 读取图片路径；未配置图片路径时显示“无资源”。

装备模板配置部位 `slotKey`、图片路径和基础属性 `stats`。装备品质不在后台模板中配置，运行时默认白色，熔炼升阶后由装备实例保存品质进度。

道具可作为任务奖励、副本奖励、邮件附件、聚妖台消耗道具或聚妖台掉落。

## 任务配置

页面：

```text
/admin/quests
```

保存到：

```text
quests.json
```

可配置：

- 任务 ID
- 分类：主线/每日
- 标题
- 描述
- 触发事件
- 完成次数
- 前置任务
- 奖励列表

当前奖励类型：

- 铜钱
- 道具

## 副本配置

页面：

```text
/admin/campaign
/admin/campaign/{chapterId}
/admin/campaign/{chapterId}/{stageId}
```

保存到：

```text
campaign.json
```

可配置：

- 章节列表
- 关卡列表
- 关卡基础信息
- 普通通关奖励
- 首通奖励
- 1 到 3 波敌人
- 每波 1 到 6 个敌人

敌人引用 `monsters.json` 的妖怪模板，并在关卡内配置等级、星级、阶级和出生坐标。

## 聚妖台配置

页面：

```text
/admin/gacha
```

保存到：

```text
gacha.json
```

可配置：

- 奖池 ID
- 奖池名称
- 奖池描述
- 消耗道具
- 掉落项类型
- 掉落项模板
- 掉落项名称
- 掉落项图片路径
- 掉落项数量
- 掉落项权重

单抽数量不配置，固定消耗 1 个道具。十连固定消耗 10 个道具。

## 邮件后台

页面：

```text
/admin/mail
```

邮件后台不是 JSON 配置，而是运营发信工具，保存到 LiteDB 集合：

```text
mail_messages
```

可填写：

- 发送范围：指定玩家 / 全服玩家
- 玩家账号
- 标题
- 发件人
- 正文
- 附件列表

全服发送会读取当前账号列表，并为每个账号写入一封邮件。

附件当前支持：

- 铜钱
- 道具

## 配置校验

保存配置时应校验：

- ID 不能为空。
- ID 不能重复。
- 名称不能为空。
- 引用的模板必须存在。
- 数量必须大于 0。
- 权重必须大于 0。
- 阵容数量必须大于 0。
- 公会等级上限必须大于 0。
- 公会等级所需总贡献必须大于 0，并逐级递增。
- 关卡最多 3 波。
- 每波最多 6 个敌人。

## 设计原则

- 玩法配置不写死在代码中。
- 后台保存 JSON 后立即更新内存配置。
- 玩家运行数据和配置数据分离。
- 邮件后台属于运营工具，可以直接写运行数据。
- 历史兼容和迁移不默认保留，结构性变动需要时可清理旧表。
