# 聚妖台

## 模块定位

聚妖台是抽卡系统的玩家入口，用于按奖池配置消耗指定道具，并按权重获得妖怪、道具、碎片等奖励。

功能不把奖池、奖励、消耗写死在代码里，所有奖池数据来自 `gacha.json`。

## 页面结构

玩家入口：

```text
/
 -> 聚妖台
```

页面路由：

```text
/gacha
/gacha/{poolId}
```

`/gacha` 是奖池首页，只显示奖池列表：

- 奖池名称
- 奖池描述
- 每抽消耗的道具名称

点击奖池后进入 `/gacha/{poolId}`，详情页才显示：

- 奖池名称
- 奖池描述
- 当前持有的消耗道具数量
- 单抽消耗：1 个消耗道具
- 十连消耗：10 个消耗道具
- 掉落预览
- 抽 1 次按钮
- 抽 10 次按钮
- 最近一次抽卡结果

## 配置文件

路径：

```text
App_Data/Configs/gacha.json
```

结构：

```json
{
  "version": 1,
  "pools": [
    {
      "id": "standard",
      "name": "寻妖池",
      "description": "可获得妖怪、碎片和养成材料",
      "costItemTemplateId": "soul-stone",
      "entries": []
    }
  ]
}
```

奖池字段：

- `id`：奖池 ID。
- `name`：奖池名称。
- `description`：奖池描述。
- `costItemTemplateId`：抽卡消耗道具模板 ID，引用 `items.json` 的 `consumables[]`。
- `pityDrawCount`：保底抽数，0 表示关闭保底。
- `pityMaxWeight`：保底过滤权重，触发保底时过滤掉权重大于该值的掉落项。
- `entries`：掉落项列表。

掉落项字段：

- `type`：掉落类型。
- `templateId`：模板 ID。铜钱不需要模板 ID。
- `name`：展示名称。
- `imagePath`：图片路径。
- `quantity`：单次命中该掉落项时发放数量。
- `weight`：权重。

## 掉落类型

当前支持：

| 类型 | 说明 |
| --- | --- |
| `Monster` | 按妖怪模板生成一个新的玩家妖怪 |
| `Consumable` | 发放道具到背包 |
| `Fragment` | 发放碎片到背包 |
| `Copper` | 发放铜钱 |

妖怪掉落通过 `templateId` 读取 `monsters.json`，生成 `OwnedMonster`。

道具掉落通过 `templateId` 读取 `items.json` 的 `consumables[]`。

碎片掉落通过 `templateId` 读取 `items.json` 的 `fragments[]`。

## 抽卡规则

抽卡接口：

```csharp
GameAccountStore.DrawGacha(userName, poolId, drawCount)
```

规则：

- `drawCount` 只允许 `1` 或 `10`。
- 单抽固定消耗 1 个奖池配置道具。
- 十连固定消耗 10 个奖池配置道具。
- 消耗道具不足时不能抽卡。
- 抽卡前校验奖池、掉落项和模板是否有效。
- 抽卡后先更新内存，再保存账号。

## 保底规则

保底按玩家和奖池分别计数。

配置示例：

```json
{
  "pityDrawCount": 100,
  "pityMaxWeight": 20
}
```

含义：

- 玩家在该奖池累计抽到第 100 抽时触发保底。
- 触发保底时，先过滤掉 `weight > 20` 的掉落项。
- 过滤后剩余掉落项不再按权重随机，而是等概率随机。
- 保底命中后，该奖池的保底计数清零。
- 未触发保底时，仍按普通权重随机。

如果过滤后没有可抽取项，配置保存时会报错。

## 后台配置

后台入口：

```text
/admin/gacha
```

后台可配置：

- 奖池 ID
- 奖池名称
- 奖池描述
- 消耗道具
- 保底抽数
- 过滤权重
- 掉落项
- 掉落项类型
- 掉落项模板
- 掉落项名称
- 掉落项图片路径
- 掉落项数量
- 掉落项权重

后台不配置单抽数量。单抽固定 1，十连固定 10。

## 当前限制

- 暂无 UP 概率。
- 暂无抽卡记录页。
- 暂无免费抽、每日折扣、首抽优惠。
- 暂未支持装备作为抽卡奖励。
