# 持久化设计

## 模块定位

运行数据使用 LiteDB 持久化，配置数据继续使用 JSON。这样可以保持策划配置易编辑，同时让玩家进度在服务重启后保留。

## 数据库

数据库文件：

```text
App_Data/GameData/xunyao.db
```

统一入口：

```csharp
GameDatabase
```

`GameDatabase` 作为单例注册，内部使用 `LiteDatabase` 和 `ConnectionType.Shared`。

## 配置数据

配置数据仍使用 JSON：

```text
App_Data/Configs/monsters.json
App_Data/Configs/items.json
App_Data/Configs/campaign.json
App_Data/Configs/quests.json
App_Data/Configs/gameplay.json
App_Data/Configs/gacha.json
```

配置数据不进入 LiteDB，原因：

- 方便人工编辑和后台配置页保存。
- 配置变更不应混入玩家运行数据。
- 便于版本管理和回滚。

## 运行数据集合

当前 LiteDB 集合：

| 集合 | Store | 说明 |
| --- | --- | --- |
| `player_accounts` | `GameAccountStore` | 账号、角色、妖怪、装备、道具、碎片、铜钱 |
| `guilds` | `GuildStore` | 公会、成员、会长、公告、贡献、等级 |
| `chat_messages` | `ChatStore` | 世界、公会、系统聊天记录 |
| `quest_states` | `QuestStore` | 玩家任务进度和领奖状态 |
| `campaign_progress` | `CampaignStore` | 玩家已通关关卡 |
| `operation_logs` | `OperationLogStore` | 奖励领取、通关、扫荡等操作日志 |
| `mail_messages` | `MailStore` | 玩家邮件、已读状态、附件领取状态 |

## 文档模型

为减少 LiteDB 对复杂运行对象的直接推断，运行对象使用专门的 Document 类保存。

主要文档：

- `PlayerAccountDocument`
- `OwnedMonsterDocument`
- `BackpackEquipmentItemDocument`
- `BackpackConsumableItemDocument`
- `BackpackFragmentItemDocument`
- `GuildDocument`
- `ChatMessageDocument`
- `QuestStateDocument`
- `CampaignProgressDocument`
- `OperationLogDocument`
- `MailMessageDocument`

## 保存策略

当前业务规则：

```text
运行内存为准
 -> 先更新内存模型
 -> 再保存 LiteDB
```

不默认使用跨 Store 事务。允许极端情况下通过日志和玩家反馈处理丢失或不一致问题。

## 账号保存

以下操作会保存账号：

- 注册账号
- 创建角色
- 装备穿戴/卸下
- 装备强化
- 装备熔炼升阶
- 妖怪升级
- 妖元吸收
- 妖怪突破
- 妖怪升星
- 任务领奖
- 副本通关奖励
- 副本扫荡奖励
- 聚妖台抽卡
- 邮件附件领取
- 公会贡献扣除铜钱

## 独立状态保存

以下操作保存独立集合：

- 创建/加入/退出公会、修改公告、公会贡献和等级变化：保存 `guilds`。
- 发送聊天和系统消息：保存 `chat_messages`。
- 任务进度变化和领奖状态：保存 `quest_states`。
- 首次通关关卡：保存 `campaign_progress`。
- 任务领奖、通关、扫荡等记录：保存 `operation_logs`。
- 发送邮件、读邮件、领取邮件附件、删除邮件：保存 `mail_messages`。

## 邮件持久化

邮件集合：

```text
mail_messages
```

索引：

- `Id` 唯一索引
- `UserName` 普通索引

字段：

- `Id`
- `UserName`
- `Title`
- `Content`
- `SenderName`
- `SentAt`
- `Read`
- `Claimed`
- `Attachments`

附件使用 `OperationRewardItemDocument` 保存，运行时转换为 `QuestReward`。

## 公会持久化

公会集合：

```text
guilds
```

字段：

- `Id`
- `Name`
- `Notice`
- `LeaderUserName`
- `Members`
- `CreatedAt`
- `TotalContribution`
- `Level`

成员字段：

- `UserName`
- `RoleName`
- `Role`
- `JoinedAt`
- `Contribution`

## 当前限制

- 没有数据库迁移版本号。
- 没有定期备份机制。
- 没有后台数据库诊断页。
- 没有跨进程写入协调测试。
- 没有事务性发奖。

## 后续扩展

- 增加数据版本和迁移脚本。
- 增加定期备份。
- 增加后台数据诊断页。
- 为排行榜增加独立快照集合。
- 为邮件增加过期清理和发送记录。
