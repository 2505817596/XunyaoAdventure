# 好友系统

## 模块定位

好友系统用于建立玩家之间的稳定社交关系，并作为好友私聊、未读提醒和会话入口的基础。

当前实现基于 Blazor Server + LiteDB：
- 好友关系和好友申请由 `FriendStore` 管理。
- 私聊消息、会话摘要和已读状态由 `ChatStore` 管理。
- 好友页面路径为 `/friends`。
- 好友私聊路径为 `/chat/{FriendUserName}`。

## 功能范围

### 查找玩家

玩家可以在好友页输入账号或角色名搜索其他玩家。

搜索规则：
- 必须已登录并创建角色。
- 不显示自己。
- 只显示已创建角色的账号。
- 搜索结果展示角色名、账号、等级和总战力。

### 好友申请

玩家可以向搜索结果中的玩家发送好友申请。

申请规则：
- 不能添加自己。
- 已是好友时不能重复添加。
- 已发送申请时显示已申请状态。
- 如果对方已经向自己发过申请，再次添加会直接互相成为好友。
- 当前好友上限为 `FriendStore.MaxFriends`，默认 `80`。

### 申请处理

好友页展示收到的好友申请。

玩家可以：
- 同意申请：双方建立双向好友关系。
- 拒绝申请：删除该申请。

### 好友列表

好友页展示当前好友列表。

每个好友展示：
- 角色名
- 账号
- 等级
- 总战力
- 最近一条私聊内容
- 最近私聊时间
- 未读私聊数量

排序规则：
1. 有未读消息的好友优先。
2. 最近有私聊消息的好友优先。
3. 其余按角色名排序。

### 删除好友

玩家可以删除好友。

删除规则：
- 双方好友关系同时删除。
- 历史私聊消息保留。
- 删除后不能继续向对方发送私聊，除非重新成为好友。

## 好友私聊

好友列表中的“私聊”按钮进入 `/chat/{FriendUserName}`。

私聊规则：
- 只能给好友发送。
- 不能给自己发送。
- 对方账号不存在或未创建角色时不能发送。
- 单条消息长度和冷却规则沿用聊天系统。

## 未读提醒

系统按玩家和好友维度记录最后已读消息 ID。

已读规则：
- 进入好友私聊窗口时，自动标记该会话已读。
- 玩家停留在当前私聊窗口时，如果收到该好友的新消息，也自动标记已读。
- 自己发送的消息不计入自己的未读数量。

展示规则：
- 主页好友按钮显示未读总数，例如 `好友（3）`。
- 好友列表每个好友显示该会话未读数量。
- 首页聊天摘要如果最新消息是私聊，点击后进入对应好友聊天窗口。

## 数据模型

`FriendRelation`：
- `UserName`：玩家账号。
- `FriendUserName`：好友账号。
- `CreatedAt`：建立好友关系时间。

`FriendRequest`：
- `FromUserName`：申请发起方。
- `ToUserName`：申请接收方。
- `CreatedAt`：申请时间。

`DirectChatReadState`：
- `UserName`：玩家账号。
- `FriendUserName`：好友账号。
- `LastReadMessageId`：该玩家对该好友会话最后已读消息 ID。

## LiteDB 集合

| 集合 | Store | 内容 |
| --- | --- | --- |
| `friend_relations` | `FriendStore` | 双向好友关系 |
| `friend_requests` | `FriendStore` | 待处理好友申请 |
| `direct_chat_read_states` | `ChatStore` | 私聊会话已读位置 |
| `chat_messages` | `ChatStore` | 世界、公会、系统和私聊消息 |

## UI 入口

主页入口：
- `好友`
- 有未读私聊时显示为 `好友（N）`

好友页：
- 查找玩家
- 好友申请
- 我的好友
- 私聊入口
- 删除好友

聊天页：
- 私聊 Tab
- 选中好友后显示当前私聊对象
- 无私聊对象时引导前往好友列表
