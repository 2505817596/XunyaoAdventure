# 后台配置系统

## 模块定位

后台配置系统用于管理游戏静态 JSON 配置，覆盖妖怪、物品、章节关卡和初始化配置。

## 存储规则

配置文件目录：

```text
App_Data/Configs/
```

配置文件：

```text
monsters.json
items.json
campaign.json
gameplay.json
```

配置文件由 `GameConfigStore` 读取和写入：

- 启动时读取 JSON。
- 如果文件不存在，只生成空配置文件。
- 后台保存后写回 JSON。
- 保存后内存配置立即更新，不需要重启。
- 创建角色赠送妖怪由 `gameplay.json` 控制，不在妖怪模板上配置。

## 妖怪模板字段

`monsters.json` 结构：

```text
version
monsters[]
```

妖怪模板字段：

- `templateId`：模板 ID，必须唯一。
- `name`：妖怪名。
- `attribute`：主属性，力/智/敏。
- `element`：元素，金/木/水/火/土。
- `position`：站位，前排/中排/后排。
- `initialLevel`：初始等级。
- `initialStar`：初始星级。
- `initialStage`：初始阶级。
- `initialPower`：初始战力。
- `unitAssetId`：战斗资源 ID，例如 001、003。
- `portraitUrl`：头像路径。
- `baseStrength` / `baseIntelligence` / `baseAgility`：基础力量、智力、敏捷。
- `strengthGrowth` / `intelligenceGrowth` / `agilityGrowth`：力量、智力、敏捷成长。
- `baseMaxHp`：基础最大生命值。
- `basePhysicalAttack`：基础物理攻击力。
- `baseMagicPower`：基础魔法强度。
- `basePhysicalArmor`：基础物理护甲。
- `baseMagicResist`：基础魔法抗性。
- `basePhysicalCrit`：基础物理暴击。
- `baseHpRegen`：基础生命回复。
- `baseEnergyRegen`：基础能量回复。
- `baseInterruptThreshold`：基础打断阈值。
- `moveSpeed`：战斗移动速度。
- `attackRange`：普攻距离。
- `attackInterval`：普攻间隔。

## 后台页面

页面路径：

```text
/admin/monsters
/admin/monsters/{templateId}
/admin/items
/admin/items/{kind}/{templateId}
/admin/gameplay
/admin/campaign
/admin/campaign/{chapterId}
/admin/campaign/{chapterId}/{stageId}
```

当前功能：

- 查看妖怪模板列表。
- 新增妖怪模板。
- 点击妖怪进入单个妖怪配置页。
- 在单个妖怪配置页编辑模板字段。
- 保存配置。
- 查看物品模板列表，按道具/装备/碎片分页。
- 点击物品进入单个物品配置页。
- 道具配置效果类型和效果数值。
- 装备配置基础属性，战力由属性和品质自动换算。
- 碎片配置品质和描述。
- 初始化配置页使用多选下拉框配置创建角色赠送妖怪。
- 查看章节列表。
- 新增章节。
- 点击章节进入该章节的关卡配置页。
- 在章节配置页编辑章节基础信息，并只显示该章节关卡列表。
- 点击关卡进入单个关卡配置页。
- 在单个关卡配置页编辑关卡基础信息、推荐战力、难度、默认解锁。
- 在单个关卡配置页编辑 1-3 波敌人。
- 在单个关卡配置页编辑每波 1-6 个敌人的妖怪模板、等级、星级、阶级和出生坐标。

玩家妖怪进入战斗时，会按 `templateId` 读取 `monsters.json` 对应模板，再叠加等级、星级、阶级、妖元和装备计算最终战斗属性。模板缺失时视为配置错误。

后台配置采用索引页加详情页结构。妖怪首页只显示名字和模板 ID，点击后进入单个妖怪配置。副本首页只显示章节，章节页只显示关卡，点击关卡后进入单个关卡配置，避免一个页面堆太多字段。

后台入口在主页，页面路径为 `/admin`。

## 初始化配置

全局初始化配置文件：

```text
gameplay.json
```

字段：

```text
initialRole.monsterTemplateIds
```

含义：创建角色时赠送的妖怪模板 ID 列表。

后台页面：

```text
/admin/gameplay
```

UI 使用多选下拉框选择妖怪模板。保存后写入 `gameplay.json`。

现在流程：

```text
读取 gameplay.json 的 initialRole.monsterTemplateIds
 -> 按模板 ID 读取 monsters.json
 -> 生成玩家 OwnedMonster
```

如果没有配置赠送妖怪，创建角色成功后初始妖怪列表为空。

装备、道具、碎片由 GM、任务、副本掉落、活动、邮件等系统发放。

## 物品配置

`items.json` 当前包含：

- `consumables[]`：道具模板。
- `equipment[]`：装备模板。
- `fragments[]`：碎片模板。

道具字段：

- `templateId`
- `name`
- `iconText`
- `effectType`
- `effectValue`
- `description`

效果类型：

| EffectType | 含义 |
| --- | --- |
| `None` | 无效果 |
| `MonsterExp` | 妖怪经验 |
| `DemonEssence` | 妖元材料 |
| `BreakthroughPill` | 破境材料 |
| `SoulStone` | 升星材料 |

装备字段：

- `templateId`
- `name`
- `slotKey`
- `iconText`
- `quality`
- `stats`
- `upgradeLevel`

装备 `stats` 包含力量、智力、敏捷、最大生命、物理攻击、魔法强度、物理护甲、魔法抗性、物理暴击、生命回复、能量回复、打断阈值。

碎片字段：

- `templateId`
- `name`
- `iconText`
- `quality`
- `description`

## 章节关卡配置

`campaign.json` 当前包含：

- `chapters[]`：章节配置。
- `stages[]`：关卡配置。
- `stages[].waves[]`：每关敌方波次，最多 3 波。
- `waves[].enemies[]`：每波敌人，最多 6 个。

章节字段：

- `id`：章节 ID。
- `name`：章节名。
- `description`：章节描述。
- `order`：显示顺序。
- `unlocked`：章节是否开放。

关卡字段：

- `id`：关卡 ID。
- `chapterId`：所属章节 ID。
- `code`：关卡编号，例如 1-1。
- `name`：关卡名。
- `description`：关卡描述。
- `order`：章节内排序。
- `recommendedPower`：推荐战力。
- `difficulty`：难度，用于奖励计算。
- `baseUnlocked`：是否默认解锁。
- `waves`：敌方波次。

敌人不是独立属性表，而是妖怪模板实例。关卡波次只配置：

- `templateId`：引用 `monsters.json` 的妖怪模板 ID。
- `name`：关卡内备注名。
- `level`：敌人等级。
- `star`：敌人星级。
- `stage`：敌人阶级。
- `x` / `y`：出生坐标。

基础三维、成长、基础生命、攻击、防御、暴击、回复、打断阈值、移动速度、攻击距离、攻击间隔全部来自妖怪模板。

运行逻辑：

- 副本章节和关卡列表读取 `campaign.json`。
- 进入战斗后，服务端按 `SelectedStage.StageId` 读取对应关卡的 `waves`。
- LeanCLR 初始化战斗时直接使用该关卡波次生成敌人。
- 如果没有配置章节或关卡，副本列表为空。

## 配置校验

保存妖怪配置时校验：

- 模板 ID 不能为空。
- 模板 ID 不能重复。
- 妖怪名不能为空。
- 主属性只能是 力/智/敏。
- 元素只能是 金/木/水/火/土。
- 站位只能是 前排/中排/后排。
- 星级范围 1-5。
- 阶级范围 1-5。
- 资源 ID 不能为空。
- 基础三维不能小于 0。
- 成长不能小于 0。
- 基础生命和基础物攻必须大于 0。
- 移速、攻击距离、攻击间隔必须大于 0。
