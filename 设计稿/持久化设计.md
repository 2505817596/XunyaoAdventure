# 持久化设计

## 模块定位

运行数据使用 LiteDB 持久化，配置数据继续使用 JSON。这样可以保持策划配置易编辑，同时让玩家进度在服务重启后保留。

## 数据库

数据库文件：

```text
App_Data/GameData/xunyao.db
```

统一入口：

```csharp
GameDatabase
```

`GameDatabase` 作为单例注册，内部使用 `LiteDatabase` 和 `ConnectionType.Shared`。

## 配置数据

配置数据仍使用 JSON：

```text
App_Data/Configs/monsters.json
App_Data/Configs/items.json
App_Data/Configs/campaign.json
App_Data/Configs/quests.json
App_Data/Configs/gameplay.json
```

原因：

- 配置数据适合人工编辑和后台配置页保存。
- 配置变更不应混入玩家运行数据。
- 便于版本管理和回滚。

## 运行数据

当前 LiteDB 集合：

| 集合 | Store | 说明 |
| --- | --- | --- |
| `player_accounts` | `GameAccountStore` | 账号、角色、妖怪、背包、铜钱 |
| `guilds` | `GuildStore` | 公会、成员、公告 |
| `chat_messages` | `ChatStore` | 世界、公会、系统聊天记录 |
| `quest_states` | `QuestStore` | 玩家任务进度和领奖状态 |
| `campaign_progress` | `CampaignStore` | 玩家已通关关卡 |

## 文档模型

为了规避 LiteDB 直接映射 C# record、嵌套列表、接口类型时的限制，复杂对象采用 JSON 字符串保存。

当前文档模型：

- `PlayerAccountDocument`
  - `UserName`
  - `AccountJson`
- `GuildDocument`
  - `Id`
  - `GuildJson`
- `ChatMessageDocument`
  - `Id`
  - `MessageJson`
- `QuestStateDocument`
  - `UserName`
  - `StatesJson`
- `CampaignProgressDocument`
  - `UserName`
  - `ClearedStageIds`

## 保存时机

- 注册账号：保存账号。
- 创建角色：保存账号。
- 背包、装备、升级、突破、升星、任务奖励导致账号变化：保存账号。
- 创建/加入/退出公会、修改公告：保存公会。
- 发送聊天和系统消息：保存聊天。
- 任务进度变化、领取奖励：保存任务状态。
- 首次通关关卡：保存通关进度。

## 当前限制

- 没有迁移版本号。
- 没有数据库备份机制。
- 没有管理后台查看数据库内容。
- 没有跨进程写入协调测试，只按单服务实例设计。
