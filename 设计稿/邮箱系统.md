# 邮箱系统

## 模块定位

邮箱系统用于向玩家发送系统邮件和附件奖励。当前实现覆盖玩家收件箱、邮件详情、附件领取、一键领取、邮件删除、后台单人发信和后台全服群发。

邮箱数据属于玩家运行数据，使用 LiteDB 持久化。

## 玩家入口

主页入口：

```text
/
 -> 邮箱
```

如果存在未读邮件，或存在未领取附件的邮件，主页按钮显示数量：

```text
邮箱（3）
```

## 页面结构

页面路由：

```text
/mail
/mail/{mailId}
```

`/mail` 是邮箱首页，只显示邮件列表，不展示正文和附件详情。

列表项显示：

- 邮件标题
- 发件人
- 发送时间
- 阅读状态
- 附件提示
- 删除按钮

附件提示只显示摘要：

- `无附件`
- `有附件`
- `附件已领取`

点击列表项进入 `/mail/{mailId}`。

邮箱首页提供“一键领取”按钮，会领取当前账号所有未领取附件的邮件。

`/mail/{mailId}` 是邮件详情页，显示：

- 标题
- 发件人
- 发送时间
- 正文
- 附件列表
- 领取附件按钮
- 删除邮件按钮

进入详情页时自动标记邮件为已读。

## 后台发信

后台入口：

```text
/admin/mail
```

后台可填写：

- 发送范围：指定玩家 / 全服玩家
- 玩家账号
- 标题
- 发件人
- 正文
- 附件列表

选择“全服玩家”时，后台会按当前账号列表给每个账号生成一封邮件；选择“指定玩家”时需要填写玩家账号。

附件类型沿用 `QuestReward`：

| 类型 | 说明 |
| --- | --- |
| `Copper` | 铜钱 |
| `Consumable` | 道具 |

道具附件必须选择 `items.json` 中的道具模板。

## 数据模型

运行模型：

```csharp
MailMessage
```

字段：

- `Id`
- `UserName`
- `Title`
- `Content`
- `SenderName`
- `SentAt`
- `Read`
- `Claimed`
- `Attachments`

附件使用：

```csharp
QuestReward
```

## 持久化

LiteDB 集合：

```text
mail_messages
```

文档模型：

```csharp
MailMessageDocument
```

字段：

- `Id`
- `UserName`
- `Title`
- `Content`
- `SenderName`
- `SentAt`
- `Read`
- `Claimed`
- `Attachments`

集合索引：

- `Id` 唯一索引
- `UserName` 普通索引

## 领取规则

领取附件流程：

```text
校验登录
 -> 查找玩家自己的邮件
 -> 校验附件是否存在
 -> 校验是否已领取
 -> 调用 GameAccountStore.GrantRewards
 -> 标记 Read = true
 -> 标记 Claimed = true
 -> 保存邮件
```

奖励发放复用账号奖励逻辑，不在邮箱里重复维护背包写入逻辑。

账号更新规则仍然是：

```text
先更新内存
再保存 LiteDB
```

## 状态含义

| 字段 | 含义 |
| --- | --- |
| `Read` | 玩家是否打开过详情页 |
| `Claimed` | 附件是否已经领取 |

没有附件的邮件只需要读信，不需要领取。

有附件的邮件即使已读，只要附件未领取，主页仍计入提醒数量。

## 删除规则

- 无附件邮件可以直接删除。
- 有附件且已领取的邮件可以删除。
- 有附件但未领取的邮件不能删除，需要先领取附件。
- 删除邮件会从内存列表和 LiteDB `mail_messages` 集合中移除。

## 当前限制

- 暂无过期时间。
- 暂无邮件模板配置。
- 暂无装备附件。
